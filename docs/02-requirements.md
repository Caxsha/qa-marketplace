# QA Marketplace — Software Requirements Specification v2.1

## 1. Регистрация и авторизация

**REQ-AUTH-001. Регистрация пользователя**
Email обязателен, корректного формата; пароль не менее 8 символов;
повторная регистрация существующего email запрещена.

**REQ-AUTH-002. Авторизация пользователя**
Вход по email и паролю. При некорректных данных — сообщение об ошибке.
Пароль не должен возвращаться в API-ответе.

**REQ-AUTH-003. Выход из аккаунта**
После выхода доступ к защищённым функциям закрыт без повторной авторизации.

## 2. Каталог позиций

**REQ-CAT-001. Просмотр каталога**
Отображается список всех позиций: товаров и услуг.

**REQ-CAT-002. Различие товара и услуги**
Для позиции типа "товар" отображается остаток на складе (stock_quantity).
Для позиции типа "услуга" отображается срок выполнения в днях (duration_days).

**REQ-CAT-002a. Бизнес-правило целостности**
- `item_type = product` → `stock_quantity >= 0`, `duration_days = NULL`
- `item_type = service` → `stock_quantity = NULL`, `duration_days > 0`

Правило проверяется на уровне API (валидация) и на уровне БД (constraint),
где это технически возможно.

**REQ-CAT-003. Поиск**
Поиск по названию, без учёта регистра.

**REQ-CAT-004. Фильтрация**
Фильтрация по категории, диапазону цен и по типу (товар/услуга).

**REQ-CAT-005. Карточка позиции**
Название, описание, цена, категория; для товара — наличие, для услуги — срок выполнения.

## 3. Корзина

**REQ-CART-001. Добавление позиции**
Авторизованный пользователь может добавить в корзину доступную позицию
(товар с остатком > 0 или любую услугу).

**REQ-CART-002. Изменение количества**
Целое число ≥ 1. Для товара — не больше остатка. Для услуги — открытый вопрос (см. OQ-011).

**REQ-CART-003. Удаление позиции**
После удаления позиция не учитывается в сумме корзины.

**REQ-CART-004. Расчёт стоимости**
Пересчитывается при любом изменении корзины.

## 4. Оформление заказа

**REQ-ORD-001. Создание заказа**
Требует хотя бы одну позицию в корзине. Заказ содержит: id, список позиций, количество,
итоговую стоимость, дату создания, статус, способ получения.

Статус заказа принимает одно из значений:
`created → awaiting_payment → paid → completed`, либо `cancelled` на любом этапе до `completed`.

**REQ-ORD-002. Проверка наличия**
Перед созданием заказа проверяется остаток каждого товара (для услуг не применяется).
Если товара недостаточно — заказ не создаётся, пользователь получает понятную ошибку.

**REQ-ORD-004. Способ получения заказа**
Пользователь выбирает: `delivery` (доставка) или `pickup` (самовывоз).
Если выбрана доставка — обязателен адрес доставки.
Если самовывоз — адрес не запрашивается.

## 5. История заказов

**REQ-ORD-003. Просмотр заказов**
Пользователь видит только свои заказы.

## 6. Общие требования

**REQ-GEN-001. Валидация входных данных**
Некорректные данные не должны приводить к созданию некорректных записей.
